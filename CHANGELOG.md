# [4.0.0] - 2026-08-05


## Breaking Changes
- Raised `swift-tools-version` from 5.7 to 6.0 (requires Xcode 16 or later)
- Raised minimum supported platform to iOS 16.0 (previously iOS 15.0); macOS is no longer a supported target
- All public provider protocols now conform to `Sendable`: `ChatProvider`, `ChatThreadProvider`, `ChatThreadListProvider`, `ConnectionProvider`, `AnalyticsProvider`, `CustomerProvider`, `CustomerCustomFieldsProvider`, `ContactCustomFieldsProvider`, `ProactiveActionProvider`. Custom protocol conformances must be `Sendable` (or `@unchecked Sendable`).
- `CXoneChat` is now `@MainActor`-isolated. Call sites from non-`@MainActor` contexts must annotate themselves `@MainActor` or wrap calls in `await MainActor.run { }`.
- Removed the `CXoneChat.shared` singleton. Construct an instance directly with `let chatProvider = CXoneChat()` and hold it for the lifetime of your app; pass that reference into your own types instead of reaching for the global.
- Removed the static `CXoneChat.signOut()`. Sign-out is now an instance method: call `chatProvider.signOut()`.
- Removed the `CXoneChatDelegate` protocol and the `add(delegate:)` / `remove(delegate:)` registry. Subscribe to events with the new `func events() -> AsyncStream<ChatEvent>` on `ChatProvider`; switch over the `ChatEvent` cases for the callbacks you previously implemented.
- Removed deprecated `ConnectionProvider` methods: `prepare(chatURL:socketURL:brandId:channelId:)`, `prepare(chatURL:socketURL:loggerURL:brandId:channelId:)`, `executeTrigger(_:)` (UUID variant).
- Removed deprecated `AnalyticsProvider` methods: `proactiveActionDisplay(data:)`, `proactiveActionClick(data:)`, `proactiveActionSuccess(_:data:)`.
- Removed deprecated UUID-typed method variants (deprecated in 3.2.0 when the SDK migrated UUID → String): `ChatThreadListProvider.load(with: UUID?)`, `ChatThreadListProvider.provider(for threadId: UUID)`, `ContactCustomFieldsProvider.get(for threadId: UUID)`, `ContactCustomFieldsProvider.set(_:for threadId: UUID)`. Use the `String` variants instead.
- `AnalyticsProvider.visitorIdString: String?` renamed to `visitorId: String?`; update call sites from `analytics.visitorIdString` to `analytics.visitorId`.
- Removed deprecated public `ActionType` enum. Use `ProactiveActionType` with typed associated data instead.
- `CXoneChat` is now `final` — subclassing is no longer permitted. Compose with the `ChatProvider` protocol instead.
- The `CXoneChatDelegate.onTokenRefreshFailed()` callback has no `ChatEvent` equivalent. Implicit OAuth token refresh is now handled by registering `CustomerProvider.setTokenDelegateListener(_:)`; a token that cannot be refreshed surfaces as `CXoneChatError.invalidAccessToken` from the outbound method.
- `Agent` personal-information fields (`firstName`, `surname`, `nickname`, `isBotUser`, `isSurveyUser`, `imageUrl`) are now optional, and `fullName` now returns `nil` (instead of an empty string) when no name is available — so the SDK can represent agents whose personal information is hidden by the backend

## Features
- `ChatProvider.events() -> AsyncStream<ChatEvent>` — subscribe to SDK events through structured concurrency. Each call returns an independent stream; cancel the enclosing `Task` to unsubscribe.
- Public `ChatEvent` enum with cases `chatUpdated(state:mode:)`, `threadUpdated(_:)`, `threadsUpdated(_:)`, `unexpectedDisconnect`, `customEventMessage(_:)`, `agentTyping(isTyping:agent:threadId:)`, `contactCustomFieldsSet`, `customerCustomFieldsSet`, `error(_:)`, `proactiveActionReceived(_:)`.
- Refactor WebSocket client for improved cancellation and reconnection behaviour
- `ChatThread.contactId: String?` is now public — read the backend-provided contact identifier of a thread.
- Add `isAiGenerated` to `Message`, indicating whether the message content was generated by an AI agent. Defaults to `false` when the backend does not provide the field.
- `CXoneChatError.featureUnavailable(String)` — thrown when a feature is intentionally disabled in the current SDK version; the associated value carries the human-readable feature name (for example, `"Explicit OAuth"`) so it can be surfaced in integrator-facing error messaging and logs.
- Implicit OAuth token lifecycle: provide the initial connection token and its expiry via `CustomerProvider.setConnectionToken(_:expiresAt:)`, and register `CustomerProvider.setTokenDelegateListener(_:)` to supply refreshed tokens. The SDK invokes the listener (returning an `OAuthToken`) shortly before the token expires (`TokenRequestReason.tokenExpired`) or after the backend rejects it at connect (`TokenRequestReason.tokenInvalid`), applies the fresh token, and resumes the pending operation — concurrent operations queue behind a single refresh. When no listener is registered, an expired token surfaces reactively as `CXoneChatError.invalidAccessToken` from the outbound method. New public types: `OAuthToken` and `TokenRequestReason`.
- `ChatThread.ownerAssignee: Agent?` is now public — the agent that owns the case (the last agent it was actually assigned to). Unlike `assignedAgent`, the owner persists across unassignment and is restored on thread recovery.

## Fixes
- Automatic reconnection now honors the retry-attempt limit for unstable connections. A socket that repeatedly connects and immediately drops no longer reconnects indefinitely; the reconnect budget is reset only once the connection is confirmed healthy.
- Automatic reconnection now rebuilds the WebSocket URL for each attempt, minting a fresh transaction token when needed, instead of replaying the URL captured at connect time. That captured URL embeds a token that expires after a few minutes, so a reconnect that started after expiry was rejected by the gateway and could never succeed.
- A single connection drop no longer consumes two reconnect attempts. The failing socket stream and the heartbeat timeout could both report the same drop and each schedule a reconnect; duplicate reports are now ignored, so the full retry budget is available.
- Automatic reconnection no longer dead-ends when rebuilding the socket URL fails (e.g. the transaction-token mint fails on a network blip). The duplicate-disconnect guard is now reset before the failure is re-handled, so the reconnect keeps retrying across the full budget instead of silently stopping after the first failure.
- Automatic reconnection now recovers from a transaction token the server has invalidated while it still looks valid on the device (e.g. signing-key rotation, session cleanup, or a backend deploy during a background window). The first attempt reuses the cached token, and every subsequent attempt mints a fresh one — previously the rejected token was replayed on every attempt, so reconnection could exhaust its entire retry budget and give up. OAuth sessions are unaffected: their token is never force-refreshed, so a transient drop never triggers an unnecessary re-authentication.
- Exhausting the automatic-reconnection retry budget no longer leaves the chat stuck in a connecting state. Previously, when every attempt failed with an error the SDK surfaced the error but did not reset its state, so a later reconnect attempt was silently ignored and the chat could not recover even after the network returned. The connection is now torn down to a recoverable state once the budget is spent, so a fresh connect succeeds.
- Chat is now reachable again after the app is reinstalled. iOS keeps keychain data across an uninstall while clearing the rest of the app's storage, so a reinstall left a stale stored identity paired with a newly generated visitor — an inconsistent combination the backend accepted but never responded to, so thread loading timed out and the chat stayed unavailable. The SDK now detects a fresh install and clears the leftover keychain data before connecting, so a reinstalled app starts from a clean, consistent identity.
